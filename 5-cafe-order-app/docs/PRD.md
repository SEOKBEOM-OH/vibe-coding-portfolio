## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 프론트엔드 UI
앱은 **주문하기**, **관리자** 두 화면으로 구성한다. 상단 헤더에서 화면을 전환한다.

### 4.1 주문하기 화면

#### 4.1.1 화면 목적
사용자가 커피 메뉴를 보고, 옵션을 선택해 장바구니에 담은 뒤, 주문을 생성하는 화면이다.  
서비스 명칭은 헤더에 **카페 U**로 표시한다.

#### 4.1.2 레이아웃
화면은 위에서 아래로 3개 영역으로 나눈다.

| 영역 | 위치 | 역할 |
| --- | --- | --- |
| 헤더 | 상단 | 서비스명과 화면 전환 |
| 메뉴 리스트 | 중앙 | 커피 메뉴 카드 나열 |
| 장바구니 | 하단 | 담은 메뉴 확인 및 주문 |

#### 4.1.3 헤더
- 왼쪽: 서비스명 `카페 U`
- 오른쪽: `주문하기`, `관리자` 버튼
- 현재 화면인 `주문하기`는 테두리로 활성화 상태를 표시한다
- `관리자`를 누르면 관리자 화면으로 이동한다

#### 4.1.4 메뉴 리스트
메뉴는 카드 형태로 가로 나열한다. 각 카드 구성은 아래와 같다.

- **이미지**: 메뉴 이미지 영역
- **메뉴명**: 예) 아메리카노(ICE), 카페라떼  
  - ICE/HOT처럼 온도가 다른 메뉴는 별도 메뉴로 취급한다
- **가격**: 기본 가격. 예) 4,000원
- **설명**: 메뉴에 대한 짧은 설명
- **옵션**: 체크박스로 복수 선택 가능
  - 샷 추가 (+500원)
  - 시럽 추가 (+0원)
- **담기 버튼**: 선택한 옵션을 반영해 장바구니에 추가한다

#### 4.1.5 장바구니
화면 하단에 고정된 영역으로, 담은 메뉴와 결제 정보를 보여준다.

- **장바구니 항목**
  - 표시 형식: `메뉴명 (선택한 옵션) X 수량 / 금액`
  - 예) `아메리카노(ICE) (샷 추가) X 1 / 4,500원`
  - 예) `아메리카노(HOT) X 2 / 8,000원`
  - 옵션이 없으면 메뉴명과 수량, 금액만 표시한다
- **총 금액**: 장바구니 항목 금액의 합계. 예) 12,500원
- **주문하기 버튼**: 장바구니 내용을 주문으로 생성한다. 실제 결제 기능은 없다

#### 4.1.6 사용자 흐름
1. 헤더에서 주문하기 화면인지 확인한다
2. 메뉴 카드에서 원하는 옵션을 체크한다
3. `담기`를 눌러 장바구니에 추가한다
4. 장바구니에서 항목, 수량, 금액을 확인한다
5. 필요하면 다른 메뉴를 추가로 담는다
6. `주문하기`를 눌러 주문을 완료한다

#### 4.1.7 기능 요구사항
- 메뉴 목록을 조회해 카드로 보여준다
- 옵션은 담기 전에 카드에서 선택한다
- `담기` 시 메뉴 기본 가격 + 선택한 옵션 가격으로 항목 금액을 계산한다
- 같은 메뉴 + 같은 옵션 조합을 다시 담으면 새 줄이 아니라 수량을 1 증가시킨다
- 장바구니 항목 금액 = 항목 단가 × 수량
- 총 금액은 장바구니 모든 항목 금액의 합이다
- 장바구니는 담기/수량 변경 시 바로 다시 그린다
- `주문하기`를 누르면 현재 장바구니로 주문을 생성하고, 장바구니를 비운다
- 사용자 인증, 결제, 회원 기능은 없다

#### 4.1.8 UI 상태
- **장바구니가 비어 있을 때**: 항목이 없고 총 금액은 0원이다. `주문하기` 버튼은 비활성화한다
- **담기 후**: 해당 항목이 장바구니에 나타나고 총 금액이 갱신된다. 메뉴 카드의 옵션 선택은 초기화한다
- **주문 완료 후**: 장바구니를 비우고, 주문이 접수되었다는 간단한 안내를 보여준다
- **메뉴가 없을 때**: 메뉴 카드 대신 메뉴가 없다는 안내를 보여준다

### 4.2 관리자 화면

#### 4.2.1 화면 목적
관리자가 주문 요약, 메뉴 재고, 개별 주문 상태를 확인하고 처리하는 화면이다.  
사용자 인증은 없으므로, 헤더의 `관리자` 버튼으로 바로 진입한다.

#### 4.2.2 레이아웃
화면은 위에서 아래로 4개 영역으로 나눈다. 본문 섹션은 테두리가 있는 박스로 구분한다.

| 영역 | 위치 | 역할 |
| --- | --- | --- |
| 헤더 | 상단 | 서비스명과 화면 전환 |
| 관리자 대시보드 | 상단 본문 | 주문 상태별 건수 요약 |
| 재고 현황 | 중단 본문 | 메뉴별 재고 조회 및 수량 조절 |
| 주문 현황 | 하단 본문 | 주문 목록 확인 및 상태 변경 |

#### 4.2.3 헤더
- 왼쪽: 서비스명 `카페 U`
- 오른쪽: `주문하기`, `관리자` 버튼
- 현재 화면인 `관리자`는 테두리로 활성화 상태를 표시한다
- `주문하기`를 누르면 주문하기 화면으로 이동한다

#### 4.2.4 관리자 대시보드
제목은 `관리자 대시보드`이며, 주문 상태 요약을 한 줄로 보여준다.

- **총 주문**: 전체 주문 건수
- **주문 접수**: 아직 제조를 시작하지 않은 주문 건수
- **제조 중**: 현재 제조 중인 주문 건수
- **제조 완료**: 제조가 끝난 주문 건수

표시 예: `총 주문 1  주문 접수 1  제조 중 0  제조 완료 0`  
주문 상태가 바뀌면 이 숫자도 바로 갱신한다.

#### 4.2.5 재고 현황
제목은 `재고 현황`이며, 메뉴별 재고를 카드로 가로 나열한다. 각 카드 구성은 아래와 같다.

- **메뉴명**: 예) 아메리카노(ICE), 아메리카노(HOT), 카페라떼
- **현재 수량**: 예) 10개
- **수량 조절 버튼**: `-`, `+`

ICE/HOT처럼 온도가 다른 메뉴는 주문하기 화면과 같이 별도 재고로 취급한다.

#### 4.2.6 주문 현황
제목은 `주문 현황`이며, 접수된 주문을 리스트로 보여준다. 각 주문 행 구성은 아래와 같다.

- **주문 일시**: 예) 7월 31일 13:00
- **주문 내역**: 메뉴명과 수량. 예) 아메리카노(ICE) x 1
  - 옵션이 있으면 메뉴명 옆에 표시한다. 예) 아메리카노(ICE) (샷 추가) x 1
  - 한 주문에 메뉴가 여러 개면 모두 보여준다
- **주문 금액**: 해당 주문의 총액. 예) 4,000원
- **상태 버튼**: 현재 주문 상태를 버튼으로 표시한다. 예) `주문 접수`

주문 상태 순서는 아래와 같다.

1. 주문 접수
2. 제조 중
3. 제조 완료

상태 버튼을 누르면 다음 단계로 바꾼다. `제조 완료`는 마지막 상태이므로 더 이상 바꾸지 않는다.

#### 4.2.7 사용자 흐름
1. 헤더에서 관리자 화면인지 확인한다
2. 대시보드에서 주문 건수와 상태 분포를 확인한다
3. 재고 현황에서 `+` / `-`로 메뉴 수량을 조절한다
4. 주문 현황에서 주문 일시, 내역, 금액을 확인한다
5. 상태 버튼을 눌러 `주문 접수` → `제조 중` → `제조 완료` 순으로 처리한다
6. 상태 변경 후 대시보드 숫자가 바뀌었는지 확인한다

#### 4.2.8 기능 요구사항
- 주문 목록을 조회해 상태별 건수를 대시보드에 보여준다
- 메뉴별 현재 재고를 조회해 카드로 보여준다
- `+`를 누르면 해당 메뉴 재고를 1 증가시키고, `-`를 누르면 1 감소시킨다
- 재고는 0 미만이 되지 않는다. 수량이 0이면 `-` 버튼은 비활성화한다
- 주문 목록은 최신 주문이 위에 오도록 보여준다
- 주문하기 화면에서 생성된 주문은 처음 상태가 `주문 접수`이다
- 상태 버튼을 누르면 다음 상태로 바꾸고, 대시보드 건수를 다시 계산한다
- 메뉴 추가/삭제, 가격 수정, 사용자 인증 기능은 이 화면에 없다

#### 4.2.9 UI 상태
- **주문이 없을 때**: 대시보드 숫자는 모두 0이다. 주문 현황에는 주문이 없다는 안내를 보여준다
- **재고가 0일 때**: 카드에 `0개`를 표시하고 `-` 버튼은 비활성화한다
- **메뉴가 없을 때**: 재고 카드 대신 메뉴가 없다는 안내를 보여준다
- **상태 변경 후**: 해당 주문 버튼 문구가 다음 상태로 바뀌고, 대시보드 건수가 갱신된다
- **제조 완료 주문**: 버튼은 `제조 완료`로 남고 비활성화한다

## 5. 백엔드
프런트엔드(`ui`)와 백엔드를 따로 개발한다.  
백엔드는 Node.js, Express를 사용하고, 데이터는 PostgreSQL에 저장한다.  
사용자 인증 및 결제 기능은 없다.

### 5.1 데이터 모델

#### 5.1.1 Menus
커피 메뉴 정보와 재고를 담는다.

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | 정수, 기본키 | 메뉴 ID |
| name | 문자열 | 커피 이름. 예) 아메리카노(ICE) |
| description | 문자열 | 메뉴 설명 |
| price | 정수 | 기본 가격(원) |
| image | 문자열 | 이미지 주소 또는 경로 |
| stock | 정수 | 재고 수량. 0 이상 |

- ICE/HOT 처럼 온도가 다른 메뉴는 서로 다른 행으로 저장한다
- 재고 수량은 관리자 화면의 재고 현황에 표시한다
- 주문하기 화면에는 이름, 설명, 가격, 이미지, 옵션을 보여준다

#### 5.1.2 Options
메뉴에 붙는 추가 옵션이다.

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | 정수, 기본키 | 옵션 ID |
| menu_id | 정수, Menus.id 참조 | 연결할 메뉴 |
| name | 문자열 | 옵션 이름. 예) 샷 추가, 시럽 추가 |
| price | 정수 | 옵션 가격(원). 예) 500, 0 |

- 한 메뉴에 옵션이 여러 개 있을 수 있다
- 사용자는 옵션을 복수 선택할 수 있다
- 항목 단가 = 메뉴 기본 가격 + 선택한 옵션 가격의 합

#### 5.1.3 Orders
주문한 건과 그 안의 주문 내용을 담는다.

**Orders (주문)**

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | 정수, 기본키 | 주문 ID |
| created_at | 일시 | 주문 일시 |
| status | 문자열 | 주문 상태. 기본값 `주문 접수` |
| total_amount | 정수 | 주문 총 금액(원) |

주문 상태 순서:

1. 주문 접수
2. 제조 중
3. 제조 완료

**Order Items (주문 내용)**  
한 주문에 메뉴가 여러 개일 수 있으므로, 주문 내용은 별도 행으로 저장한다.

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | 정수, 기본키 | 주문 내용 ID |
| order_id | 정수, Orders.id 참조 | 소속 주문 |
| menu_id | 정수, Menus.id 참조 | 주문한 메뉴 |
| name | 문자열 | 주문 당시 메뉴 이름 |
| quantity | 정수 | 수량 |
| options | 문자열 또는 JSON | 선택한 옵션 이름/가격 목록 |
| amount | 정수 | 해당 줄 금액. 단가 × 수량 |

- `total_amount`는 모든 주문 내용 `amount`의 합이다
- 주문 이후 메뉴 이름이나 가격이 바뀌어도 주문 당시 값이 남도록 이름과 금액을 함께 저장한다

### 5.2 데이터 스키마를 위한 사용자 흐름

1. **메뉴 표시**  
   Menus 내용을 가져와 브라우저에 보여준다.  
   이름, 설명, 가격, 이미지는 주문하기 화면에 표시하고, 재고 수량은 관리자 화면의 재고 현황에 표시한다.  
   각 메뉴에 연결된 Options도 함께 불러와 주문하기 화면의 체크박스로 보여준다.

2. **장바구니 담기**  
   사용자가 커피 메뉴와 옵션을 선택해 담으면, 선택 정보는 브라우저 장바구니에 표시된다.  
   장바구니는 화면 상태이며, 담기 단계에서는 데이터베이스에 저장하지 않는다.

3. **주문 저장**  
   장바구니에서 `주문하기`를 누르면 주문 정보를 Orders에 저장한다.  
   주문 일시(`created_at`)와 주문 내용(메뉴, 수량, 옵션, 금액)을 담고, 상태는 `주문 접수`로 둔다.  
   주문한 수량만큼 해당 Menus의 재고(`stock`)를 줄인다.

4. **관리자 주문 현황**  
   Orders 정보를 관리자 화면의 주문 현황에 보여준다.  
   기본 상태는 `주문 접수`이다. 상태 버튼을 누르면 `제조 중` → `제조 완료` 순으로 바뀐다.  
   `제조 완료`는 마지막 상태이므로 더 이상 바꾸지 않는다.

### 5.3 API 설계
기본 URL은 백엔드 서버 주소이다. 예) `http://localhost:3000`  
응답은 JSON을 사용한다.

#### 5.3.1 메뉴 목록 조회
주문하기 화면(헤더의 `주문하기`)에 들어오면 데이터베이스에서 커피 메뉴 목록을 불러와 보여준다.

- **메서드/경로**: `GET /menus`
- **설명**: Menus와 연결된 Options를 함께 반환한다
- **성공 응답 예**

```json
[
  {
    "id": 1,
    "name": "아메리카노(ICE)",
    "description": "차갑고 깔끔한 블랙 에스프레소",
    "price": 4000,
    "image": "https://example.com/americano-ice.jpg",
    "stock": 10,
    "options": [
      { "id": 1, "name": "샷 추가", "price": 500 },
      { "id": 2, "name": "시럽 추가", "price": 0 }
    ]
  }
]
```

- 주문하기 화면은 이름, 설명, 가격, 이미지, 옵션을 카드에 표시한다
- `stock`은 관리자 화면 재고 현황에 표시한다

#### 5.3.2 주문 생성
사용자가 커피를 담고 `주문하기` 버튼을 누르면 주문 정보를 데이터베이스에 저장한다.  
저장한 뒤, 주문 수량만큼 해당 메뉴의 재고도 수정한다.

- **메서드/경로**: `POST /orders`
- **요청 본문 예**

```json
{
  "items": [
    {
      "menuId": 1,
      "quantity": 1,
      "optionIds": [1]
    },
    {
      "menuId": 2,
      "quantity": 2,
      "optionIds": []
    }
  ]
}
```

- **처리 규칙**
  - 메뉴/옵션 ID가 없으면 오류를 반환한다
  - 서버에서 단가와 금액을 계산한다. 클라이언트가 보낸 금액은 믿지 않는다
  - 항목 금액 = (메뉴 가격 + 선택 옵션 가격 합) × 수량
  - 주문 총액은 항목 금액의 합이다
  - `created_at`은 서버 시각으로 저장한다
  - `status`는 `주문 접수`로 저장한다
  - 각 메뉴 `stock`에서 주문 수량을 뺀다
  - 재고가 주문 수량보다 부족하면 주문을 저장하지 않고 오류를 반환한다
  - 재고는 0 미만이 되지 않는다
- **성공 응답 예**: 저장된 주문 전체(아래 5.3.3과 같은 형태). HTTP 201

#### 5.3.3 주문 단건 조회
주문 ID를 전달하면 해당 주문 정보를 보여준다.

- **메서드/경로**: `GET /orders/:id`
- **성공 응답 예**

```json
{
  "id": 12,
  "createdAt": "2026-07-31T13:00:00.000Z",
  "status": "주문 접수",
  "totalAmount": 12500,
  "items": [
    {
      "menuId": 1,
      "name": "아메리카노(ICE)",
      "quantity": 1,
      "options": [{ "name": "샷 추가", "price": 500 }],
      "amount": 4500
    },
    {
      "menuId": 2,
      "name": "아메리카노(HOT)",
      "quantity": 2,
      "options": [],
      "amount": 8000
    }
  ]
}
```

- 주문이 없으면 HTTP 404를 반환한다

#### 5.3.4 관리자용 추가 API
관리자 화면이 동작하려면 아래 API도 필요하다.

| 메서드/경로 | 설명 |
| --- | --- |
| `GET /orders` | 주문 목록 조회. 최신 주문이 위에 오도록 반환한다. 관리자 주문 현황과 대시보드에 사용한다 |
| `PATCH /orders/:id/status` | 주문 상태를 다음 단계로 변경한다. `주문 접수` → `제조 중` → `제조 완료`. `제조 완료`에서는 변경하지 않는다 |
| `PATCH /menus/:id/stock` | 관리자가 재고를 `+1` 또는 `-1`로 조절한다. 재고는 0 미만이 되지 않는다 |

**상태 변경 요청 예**

```json
{ "status": "제조 중" }
```

**재고 조절 요청 예**

```json
{ "delta": -1 }
```
