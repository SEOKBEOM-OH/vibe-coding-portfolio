## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 프론트엔드 UI
앱은 **주문하기**, **관리자** 두 화면으로 구성한다. 상단 헤더에서 화면을 전환한다.

### 4.1 주문하기 화면

#### 4.1.1 화면 목적
사용자가 커피 메뉴를 보고, 옵션을 선택해 장바구니에 담은 뒤, 주문을 생성하는 화면이다.  
서비스 명칭은 헤더에 **카페 U**로 표시한다.

#### 4.1.2 레이아웃
화면은 위에서 아래로 3개 영역으로 나눈다.

| 영역 | 위치 | 역할 |
| --- | --- | --- |
| 헤더 | 상단 | 서비스명과 화면 전환 |
| 메뉴 리스트 | 중앙 | 커피 메뉴 카드 나열 |
| 장바구니 | 하단 | 담은 메뉴 확인 및 주문 |

#### 4.1.3 헤더
- 왼쪽: 서비스명 `카페 U`
- 오른쪽: `주문하기`, `관리자` 버튼
- 현재 화면인 `주문하기`는 테두리로 활성화 상태를 표시한다
- `관리자`를 누르면 관리자 화면으로 이동한다

#### 4.1.4 메뉴 리스트
메뉴는 카드 형태로 가로 나열한다. 각 카드 구성은 아래와 같다.

- **이미지**: 메뉴 이미지 영역
- **메뉴명**: 예) 아메리카노(ICE), 카페라떼  
  - ICE/HOT처럼 온도가 다른 메뉴는 별도 메뉴로 취급한다
- **가격**: 기본 가격. 예) 4,000원
- **설명**: 메뉴에 대한 짧은 설명
- **옵션**: 체크박스로 복수 선택 가능
  - 샷 추가 (+500원)
  - 시럽 추가 (+0원)
- **담기 버튼**: 선택한 옵션을 반영해 장바구니에 추가한다

#### 4.1.5 장바구니
화면 하단에 고정된 영역으로, 담은 메뉴와 결제 정보를 보여준다.

- **장바구니 항목**
  - 표시 형식: `메뉴명 (선택한 옵션) X 수량 / 금액`
  - 예) `아메리카노(ICE) (샷 추가) X 1 / 4,500원`
  - 예) `아메리카노(HOT) X 2 / 8,000원`
  - 옵션이 없으면 메뉴명과 수량, 금액만 표시한다
- **총 금액**: 장바구니 항목 금액의 합계. 예) 12,500원
- **주문하기 버튼**: 장바구니 내용을 주문으로 생성한다. 실제 결제 기능은 없다

#### 4.1.6 사용자 흐름
1. 헤더에서 주문하기 화면인지 확인한다
2. 메뉴 카드에서 원하는 옵션을 체크한다
3. `담기`를 눌러 장바구니에 추가한다
4. 장바구니에서 항목, 수량, 금액을 확인한다
5. 필요하면 다른 메뉴를 추가로 담는다
6. `주문하기`를 눌러 주문을 완료한다

#### 4.1.7 기능 요구사항
- 메뉴 목록을 조회해 카드로 보여준다
- 옵션은 담기 전에 카드에서 선택한다
- `담기` 시 메뉴 기본 가격 + 선택한 옵션 가격으로 항목 금액을 계산한다
- 같은 메뉴 + 같은 옵션 조합을 다시 담으면 새 줄이 아니라 수량을 1 증가시킨다
- 장바구니 항목 금액 = 항목 단가 × 수량
- 총 금액은 장바구니 모든 항목 금액의 합이다
- 장바구니는 담기/수량 변경 시 바로 다시 그린다
- `주문하기`를 누르면 현재 장바구니로 주문을 생성하고, 장바구니를 비운다
- 사용자 인증, 결제, 회원 기능은 없다

#### 4.1.8 UI 상태
- **장바구니가 비어 있을 때**: 항목이 없고 총 금액은 0원이다. `주문하기` 버튼은 비활성화한다
- **담기 후**: 해당 항목이 장바구니에 나타나고 총 금액이 갱신된다. 메뉴 카드의 옵션 선택은 초기화한다
- **주문 완료 후**: 장바구니를 비우고, 주문이 접수되었다는 간단한 안내를 보여준다
- **메뉴가 없을 때**: 메뉴 카드 대신 메뉴가 없다는 안내를 보여준다

### 4.2 관리자 화면

#### 4.2.1 화면 목적
관리자가 주문 요약, 메뉴 재고, 개별 주문 상태를 확인하고 처리하는 화면이다.  
사용자 인증은 없으므로, 헤더의 `관리자` 버튼으로 바로 진입한다.

#### 4.2.2 레이아웃
화면은 위에서 아래로 4개 영역으로 나눈다. 본문 섹션은 테두리가 있는 박스로 구분한다.

| 영역 | 위치 | 역할 |
| --- | --- | --- |
| 헤더 | 상단 | 서비스명과 화면 전환 |
| 관리자 대시보드 | 상단 본문 | 주문 상태별 건수 요약 |
| 재고 현황 | 중단 본문 | 메뉴별 재고 조회 및 수량 조절 |
| 주문 현황 | 하단 본문 | 주문 목록 확인 및 상태 변경 |

#### 4.2.3 헤더
- 왼쪽: 서비스명 `카페 U`
- 오른쪽: `주문하기`, `관리자` 버튼
- 현재 화면인 `관리자`는 테두리로 활성화 상태를 표시한다
- `주문하기`를 누르면 주문하기 화면으로 이동한다

#### 4.2.4 관리자 대시보드
제목은 `관리자 대시보드`이며, 주문 상태 요약을 한 줄로 보여준다.

- **총 주문**: 전체 주문 건수
- **주문 접수**: 아직 제조를 시작하지 않은 주문 건수
- **제조 중**: 현재 제조 중인 주문 건수
- **제조 완료**: 제조가 끝난 주문 건수

표시 예: `총 주문 1  주문 접수 1  제조 중 0  제조 완료 0`  
주문 상태가 바뀌면 이 숫자도 바로 갱신한다.

#### 4.2.5 재고 현황
제목은 `재고 현황`이며, 메뉴별 재고를 카드로 가로 나열한다. 각 카드 구성은 아래와 같다.

- **메뉴명**: 예) 아메리카노(ICE), 아메리카노(HOT), 카페라떼
- **현재 수량**: 예) 10개
- **수량 조절 버튼**: `-`, `+`

ICE/HOT처럼 온도가 다른 메뉴는 주문하기 화면과 같이 별도 재고로 취급한다.

#### 4.2.6 주문 현황
제목은 `주문 현황`이며, 접수된 주문을 리스트로 보여준다. 각 주문 행 구성은 아래와 같다.

- **주문 일시**: 예) 7월 31일 13:00
- **주문 내역**: 메뉴명과 수량. 예) 아메리카노(ICE) x 1
  - 옵션이 있으면 메뉴명 옆에 표시한다. 예) 아메리카노(ICE) (샷 추가) x 1
  - 한 주문에 메뉴가 여러 개면 모두 보여준다
- **주문 금액**: 해당 주문의 총액. 예) 4,000원
- **상태 버튼**: 현재 주문 상태를 버튼으로 표시한다. 예) `주문 접수`

주문 상태 순서는 아래와 같다.

1. 주문 접수
2. 제조 중
3. 제조 완료

상태 버튼을 누르면 다음 단계로 바꾼다. `제조 완료`는 마지막 상태이므로 더 이상 바꾸지 않는다.

#### 4.2.7 사용자 흐름
1. 헤더에서 관리자 화면인지 확인한다
2. 대시보드에서 주문 건수와 상태 분포를 확인한다
3. 재고 현황에서 `+` / `-`로 메뉴 수량을 조절한다
4. 주문 현황에서 주문 일시, 내역, 금액을 확인한다
5. 상태 버튼을 눌러 `주문 접수` → `제조 중` → `제조 완료` 순으로 처리한다
6. 상태 변경 후 대시보드 숫자가 바뀌었는지 확인한다

#### 4.2.8 기능 요구사항
- 주문 목록을 조회해 상태별 건수를 대시보드에 보여준다
- 메뉴별 현재 재고를 조회해 카드로 보여준다
- `+`를 누르면 해당 메뉴 재고를 1 증가시키고, `-`를 누르면 1 감소시킨다
- 재고는 0 미만이 되지 않는다. 수량이 0이면 `-` 버튼은 비활성화한다
- 주문 목록은 최신 주문이 위에 오도록 보여준다
- 주문하기 화면에서 생성된 주문은 처음 상태가 `주문 접수`이다
- 상태 버튼을 누르면 다음 상태로 바꾸고, 대시보드 건수를 다시 계산한다
- 메뉴 추가/삭제, 가격 수정, 사용자 인증 기능은 이 화면에 없다

#### 4.2.9 UI 상태
- **주문이 없을 때**: 대시보드 숫자는 모두 0이다. 주문 현황에는 주문이 없다는 안내를 보여준다
- **재고가 0일 때**: 카드에 `0개`를 표시하고 `-` 버튼은 비활성화한다
- **메뉴가 없을 때**: 재고 카드 대신 메뉴가 없다는 안내를 보여준다
- **상태 변경 후**: 해당 주문 버튼 문구가 다음 상태로 바뀌고, 대시보드 건수가 갱신된다
- **제조 완료 주문**: 버튼은 `제조 완료`로 남고 비활성화한다
